# 유캔 프리젠터 (웹 프로토타입)

PPT / PDF 를 **트리플 모니터**로 운용하는 발표 운영 도구. 설치 없이 Chrome 에서 동작합니다.

```
┌─ 1번 모니터 ─────────┐  ┌─ 2번 모니터 ──────────────┐  ┌─ 3번 모니터 ───────────┐
│  관객 화면            │  │  연사 화면                 │  │  컨트롤 콘솔           │
│  내용만 (UI 0)        │  │  내용 + 타이머 + 다음 장    │  │  슬라이드·타이머·큐·   │
│                      │  │  + 오퍼레이터 큐 메시지     │  │  블랙아웃 조작         │
└──────────────────────┘  └───────────────────────────┘  └────────────────────────┘
```

---

## 두 가지 모드

| | **라이브 모드 (PPT)** | **PDF 모드** |
|---|---|---|
| 애니메이션 | **원본 100% 보존** (파워포인트가 직접 그림) | 없음 (PDF 특성) |
| 1번 모니터 | 파워포인트 전체화면 **그 자체** (지연 0) | 이 앱이 렌더 |
| 2번 모니터 | 1번 화면의 실시간 미러 + 타이머 | 앱이 렌더 + 타이머 + 다음 장 |
| 슬라이드 이동 | 파워포인트에서 직접 (리모컨/키보드) | 앱에서 조작 (썸네일 점프 가능) |
| 블랙아웃/로고 | ✕ (파워포인트 <kbd>B</kbd>/<kbd>W</kbd> 사용) | ○ |
| 다음 장 미리보기 | ✕ | ○ |

> 핵심 설계: **PPT 를 3개로 복제하지 않는다.** 파워포인트는 1번 모니터에 하나만 띄우고,
> 2번 모니터는 그 화면을 실시간으로 받아서 타이머를 얹는다. 그래서 애니메이션이 그대로 산다.
> 지연(1~3프레임)은 관객이 아니라 **연사 쪽**이 먹는다.

## 실행

- **Windows**: `presenter\start.bat` 더블클릭 → 브라우저가 자동으로 열립니다
  (Python 이나 Node.js 중 하나가 깔려 있어야 합니다. 없으면 안내가 뜹니다)
- **macOS / Linux**: `./presenter/serve.sh`

```bash
./presenter/serve.sh          # 기본 8123 포트
# → http://localhost:8123/presenter/ 를 Chrome 또는 Edge 로 연다
```

`file://` 로 열면 동작하지 않습니다. 화면 캡처·창 관리 API 는 **보안 컨텍스트**(localhost 또는 https)에서만 허용됩니다.

## 행사 전 세팅 순서

1. **윈도우 디스플레이 설정 → ‘확장’** (복제 모드면 전부 실패합니다)
2. 컨트롤 콘솔을 **3번 모니터**에서 연다
3. `화면 감지 / 권한 요청` → 창 관리 권한 허용 → 관객/연사 화면 배정
4. 소스 선택
   - **PPT 라이브**: 파워포인트를 1번 모니터에 전체화면으로 띄운 뒤 → `라이브 화면 캡처 시작` → 1번 화면 선택
     - 파워포인트 설정: **슬라이드 쇼 탭 → ‘발표자 도구 사용’ 체크 해제**, 모니터를 1번으로 지정
       (모니터가 3개면 파워포인트가 발표자 도구를 임의의 모니터에 띄워버립니다)
   - **PDF**: 파일 선택
5. `발표 화면 열기` → 각 화면을 **한 번 클릭**(또는 <kbd>F</kbd>)하면 전체화면
   - 브라우저는 사용자 제스처 없이 전체화면을 허용하지 않습니다. 한 번 들어간 뒤에는
     작은 안내 배지로만 남아 공연 중 화면을 가리지 않습니다.
6. 하단 **프리플라이트** 가 전부 ✓ 인지 확인

컨트롤 콘솔을 새로고침했다면 `발표 화면 열기` 를 한 번 더 누르면 기존 창이 재연결됩니다.

## 단축키

| 키 | 동작 |
|---|---|
| <kbd>→</kbd> <kbd>Space</kbd> <kbd>PageDown</kbd> | 다음 장 |
| <kbd>←</kbd> <kbd>PageUp</kbd> | 이전 장 |
| <kbd>T</kbd> | 타이머 시작 / 일시정지 |
| <kbd>R</kbd> | 타이머 리셋 |
| <kbd>B</kbd> | 블랙아웃 (PDF 모드) |
| <kbd>F</kbd> | (발표 화면에서) 전체화면 |

연사 화면에서 누른 방향키·<kbd>T</kbd> 도 컨트롤 콘솔로 전달됩니다 — 연사가 직접 넘겨도 상태가 갈라지지 않습니다.

## 구조

```
presenter/
├─ index.html        컨트롤 콘솔 (3번 모니터)
├─ screen.html       발표 화면 (?role=audience | stage)
├─ js/bus.js         창 간 상태 버스 + 타이머 계산(순수 함수)
├─ js/control.js     상태 소유자. 모든 조작이 여기로 모인다
├─ js/viewer.js      받아서 그리기만
├─ js/pdf-source.js  pdf.js 래퍼
└─ vendor/pdfjs/     pdf.js 5.4.149 번들 내장 (행사장 인터넷 없이 동작)
```

- 상태는 `BroadcastChannel` 로 전파. 타이머는 **절대 시각(epoch)** 만 공유하고 각 창이 따로 계산 → 창이 늘어나도 드리프트 없음
- PDF 는 `blob:` URL 하나를 모든 창이 공유 (동일 출처 교차 창 접근 — 실제 Chromium 에서 검증됨)
- `MediaStream` 은 구조화 복제가 안 되므로 동일 출처 창에 **직접 전달**(`window.ycpReceiveStream`)

## 검증 상태

Chromium(Playwright) 자동 테스트 19항목 통과:
PDF 로드·썸네일·3창 동기화·슬라이드 이동·키보드 위임·타이머 구동/초과·큐 메시지·블랙아웃/로고·콘솔 에러 0.

**실제 모니터 3대 환경에서는 아직 검증하지 못했습니다** (이 개발 컨테이너는 단일 가상 디스플레이).
현장에서 확인이 필요한 항목:

- `getScreenDetails()` 로 받은 좌표에 창이 정확히 열리는지 (멀티 DPI 혼용 환경)
- 지정 화면 전체화면(`requestFullscreen({screen})`) 동작
- 라이브 캡처의 체감 지연과 CPU/GPU 부하 (노트북 발열·팬)
- 파워포인트 ‘발표자 도구 해제 + 모니터 1 지정’ 조합이 3모니터에서 안정적인지

## 알려진 한계

- **Chrome/Edge 전용.** Safari·Firefox 는 Window Management API 미지원 → 창은 열리지만 자동 배치 안 됨
- 라이브 모드에서 1번 모니터는 파워포인트 소유 → 브라우저가 블랙아웃을 덮을 수 없음
- 컨트롤 콘솔 창을 닫으면 PDF `blob:` URL 이 해제되어 발표 화면이 비워짐 (콘솔은 켜둘 것)
- macOS 는 별도 검증 필요 (화면 기록 권한, 전체화면 동작 차이)
